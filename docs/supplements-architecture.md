# Система добавок: потоки данных, связи с конфигом плана и устойчивость

## Обзор
Система добавок строится вокруг трёх слоёв:
- Хранилище БД/Pinia (`suppPlan`, `supplements`, `planner`) — источник правды по плану и сущностям.
- Компосаблы (логика вычислений) — `useSupplementPlannerData`, `useSupplementPlannerLogic`, `usePlanLocks`.
- UI (`src/pages/Supplements.vue` + компоненты вкладок) — отображение, локальная отметка выполненности, действия.

Ключевая идея: БД хранит состав плана по дням и слотам, UI рендерит ближайший день и «весь план», а факт выполнения конкретного приёма хранится локально (localStorage) как чеклист за конкретную календарную дату.

## Данные и хранилища
- `planner` (Pinia): текущая программа тренинга (id, config, даты). `planner.currentProgram` определяет `program_id` для всех операций с планом добавок.
- `supplements` (Pinia): каталог добавок (id, названия, дефолтные дозы/единицы) — используется для автозаполнения дозировки при привязке к дню.
- `suppPlan` (Pinia): план добавок на дни/слоты. Кэш ключуется строкой `${program_id}:${cycle_type}:${day_index}`.
  - `attachSupplementToDay({ program_id, cycle_type, day_index, supplement_id, slot, amount, unit })`
  - `listForDayDetailed(program_id, cycle_type, day_index)` — читает из БД, обновляет кэш, отдаёт детализированные записи (с названиями/единицами).
  - `updateDaySupplement(id, patch)`, `deleteDaySupplement(id)` и групповые операции для слота.

## Компосаблы
- `useSupplementPlannerData`:
  - `cfgSupp`: конфиг плана добавок из `planner.currentProgram.config` (разбирается JSON):
    - `cycleType`: 'weekly' | 'custom'
    - `weekly.days`: массив 7 чисел (0 — нет приёмов, >0 — есть)
    - `custom.days`: массив шаблона по дням цикла
    - `startDate`: unix ms (дата начала плана)
  - `dayItems`: записи плана для ближайшего дня (детализированные).
  - `summary`: краткая сводка для UI.
- `useSupplementPlannerLogic`:
  - `findNextDayIndex()` — вычисляет ближайший «активный» день по конфигу относительно сегодня (возвращает тип цикла, индексы и смещение дней).
  - `reloadDayItems()` — грузит записи для ближайшего дня через `suppPlan`.
  - Хелперы: `dayOfWeekLabel`, `getMaxSlotsForDay`, и т.п.
- `usePlanLocks`/`computePlanLocks`:
  - Унифицирует блокировки действий по дате: «план не начался», «будущий день», «строго только сегодня» (опция `onlyToday`).

## UI и поведение
- `src/pages/Supplements.vue`:
  - Вкладка «Ближайший»: рендерится `SuppNextTab` c данными ближайшего дня.
  - Вкладка «Весь план»: рендер всего цикла/шаблона с возможностью редактирования.
  - Отметка выполненности: локальное состояние `completedSet` хранится в `localStorage` с ключом `supp_done_${programId}_${YYYY-MM-DD}`.
- `SuppNextTab.vue`:
  - Получает сгруппированные по слотам записи ближайшего дня (`grouped`), сводку, даты (`nextDateISO`, `planStartISO`) и колбэки.
  - Блокирует отметку выполненности для дней ≠ today (через `computePlanLocks(..., onlyToday: true)`).
  - Дополнительный блок: «Невыполнено (вчера)» — показывает только невыполненные записи прошлого дня и даёт их отметить независимо от блокировок.

## «Невыполненные за вчера»: как это работает
- В `Supplements.vue` добавлены:
  - `prevCompletedSet`: локальные отметки за вчера (localStorage по ключу даты предыдущего дня относительно ближайшего дня).
  - `loadPrevIncomplete()`: определяет календарную дату «вчера» относительно `nextDateISO`, вычисляет `cycleType/dayIndex` для этой даты по конфигу и грузит записи `suppPlan.listForDayDetailed`; фильтрует только те, что не отмечены выполненными вчера.
  - `toggleCompletedPrev(id)`: обновляет `prevCompletedSet`, сохраняет в localStorage, удаляет запись из списка «невыполнено» сразу для живого UI-отклика.
- В `SuppNextTab` добавлены пропсы `prevIncomplete`, `prevDateLabel`, `isCompletedPrev` и событие `toggle-item-prev`.

## Блокировки и ограничения
- Вкладка «Ближайший»:
  - Отметка за ближайший день разрешена только если этот день — сегодня. Иначе элементы карточек подсвечиваются предупреждением/дизейблятся (см. `computePlanLocks`).
  - Раздел «Невыполнено (вчера)» всегда разрешён к отметке (чтобы не терять долги, даже если ближайший день — завтра/будущее).

## Связь с конфигом тренировочного плана
- Жёстких миграций нет: записи плана добавок в БД лежат отдельно и ключуются `(program_id, cycle_type, day_index, slot)`.
- Что произойдёт при изменении `config`:
  - Изменение `cycleType` (weekly ↔ custom):
    - Существующие записи старого типа в БД останутся, но UI «Ближайший/Весь план» будет грузить записи только для текущего `cycleType`. Старые записи станут «осиротевшими» (не отображаются) до тех пор, пока вы не вернёте тип или не сделаете миграцию.
  - Изменение массива `weekly.days` или `custom.days`:
    - Дни, у которых теперь 0 (неактивные), перестанут отображаться/учитываться. Записи в БД не удаляются автоматически, но интерфейс их не покажет.
  - Изменение `startDate`:
    - Сдвигает вычисление «ближайшего дня» и индексы для custom-цикла; сами записи БД не обнуляются.
- Риск «обнуления плана добавок» при изменении конфига: данных в БД не теряется, но UI может перестать показывать часть записей, если они больше не соответствуют текущему конфигу (тип цикла/активность дня). Это выглядит как «обнуление», хотя записи по факту остаются в таблице.

### Рекомендации по устойчивости
- Перед сменой `cycleType` решите стратегию миграции: либо предупреждать пользователя, либо переносить записи между типами (маппинг индексов), либо хранить оба варианта и явно переключать режим отображения.
- При изменении активных дней (`days`):
  - Предупреждать, что скрытые дни не удаляются, но пропадут из отображения.
  - Опционально: предоставлять кнопку «очистить скрытые дни»
- Не трогать localStorage ключи прошлых дат — это позволяет корректно показывать «невыполнено (вчера)» даже после коррекции плана.

## Формат ключей localStorage
- Ближайший/сегодня: `supp_done_${programId}_${YYYY-MM-DD}`
- Вчера (для блока «невыполнено»): ключ с датой вчера относительно `nextDateISO`. Это важно: если «ближайший» — завтра, «вчера» вычисляется от завтрашнего дня (то есть «сегодня»), чтобы не терять связность по UI-логике.

## Краевые случаи
- План ещё не начался (`startDate > today`) — всё заблокировано, раздел «вчера» пустой.
- Custom-цикл и «вчера» до `startDate` — раздел «вчера» пустой.
- Выходные/неактивные дни — «вчера» может не иметь записей (список пустой, раздел скрывается).
- Смена `program_id` — ключи localStorage будут другие; отметки не «переедут» между программами (ожидаемо).

## Итог
- Планы добавок живут отдельно от тренировочного конфига. Изменения конфига не удаляют данные, но могут скрывать/переиндексировать дни при отображении.
- Вкладка «Ближайший» теперь показывает ближайший активный день и «долги» за предыдущий день. Это улучшает UX без компромисса безопасности данных.
