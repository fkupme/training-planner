# BRD 03 — Дневник (TrainingDiary)

> **Статус реализации:** COMPLETE · **Приоритет:** P1
> **Роут:** `/diary` (таб) · **Основные сторы:** `sessions`, `stats` (`stats.api`)
> **Компоненты:** `DiaryTabHistory`, `DiaryTabStats`, `SessionDetailsPopup`, `Diary/Stats/*` (графики)

## 1. Назначение

Дневник — **канонический «журнал результатов»** приложения (роль, которую `pages.md` отводил
разделу «Результаты»). Две вкладки: **История** (поиск/фильтр по прошлым сессиям + детали) и
**Статистика** (графики объёма, распределения по группам мышц и т.п.).

## 2. Пользовательские сценарии

- Как тренирующийся, я хочу пролистать прошлые тренировки и открыть детали конкретной.
- Как тренирующийся, я хочу найти сессию по упражнению/дате.
- Как тренирующийся, я хочу видеть динамику: объём во времени, баланс по группам мышц.
- Как тренирующийся, я хочу выгрузить/поделиться статистикой.

## 4. Данные

- Читает: `training_sessions`, `session_exercise_sets`; агрегации считает `stats.api`.
- Записей не создаёт (только чтение и агрегация).

## 5. Состояния экрана

- **Пусто:** нет истории → заглушка «пока нет тренировок».
- **Загрузка:** скелетоны истории/графиков.
- **Наполнено:** списки и графики.

## 6. Валидации и правила

- Агрегации устойчивы к пустым/частичным сессиям (не падать на 0 подходов).
- История не фильтруется по программе → прошлые сессии видны даже после смены плана (важно на фоне бага удаления плана в [01 §9]).
