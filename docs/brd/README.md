# BRD — бизнес-требования по разделам

Это рабочий свод требований к приложению **Training Planner**: что каждый экран должен
делать, зачем, какие данные трогает и что с ним не так сегодня. Пишем «человеческим»
языком — так, чтобы можно было спорить о продукте, а не о коде.

Документ синхронизирован с фактической реализацией (ревизия кода от 2026-07-19):
у каждого требования есть **Статус**, а расхождения между задумкой и кодом собраны
в разделе «Открытые вопросы». Это делает свод пригодным для аудита агентом `brd-auditor`.

> Источник задумки — `pages.md` (ранний черновик). Где он расходится с кодом, приоритет
> у решения, зафиксированного здесь.

## Как читать

**Статус реализации раздела:** `COMPLETE` (работает) · `PARTIAL` (частично) · `STUB` (заглушка).

**Приоритет раздела:** `P0` (ядро, без него продукта нет) · `P1` (важно для «зафиналить») · `P2` (потом).

**Статус требования (в таблицах FR):** ✅ реализовано · 🟡 частично · ⛔ не реализовано.

**Приоритет требования (MoSCoW):** `Must` · `Should` · `Could` · `Won't` (пока).

## Шаблон раздела

Каждый файл раздела следует одной структуре:

1. **Назначение** — зачем экран, основная работа пользователя.
2. **Пользовательские сценарии** — «Как <роль>, я хочу <действие>, чтобы <ценность>».
3. **Функциональные требования** — таблица `FR-XXX` с приоритетом и статусом.
4. **Данные** — какие сущности/таблицы читает и пишет.
5. **Состояния экрана** — пусто / загрузка / ошибка / наполнено / оффлайн.
6. **Валидации и правила**.
7. **Связи с другими разделами**.
8. **Открытые вопросы** — таблица `OQ` с маршрутизацией «Кому» (бизнес / разработка / PM).
9. **Известные баги и долги** — из ревизии кода, с ссылками `file:line`.

## Большие открытые продуктовые решения

Эти вопросы определяют объём всего свода — их надо закрыть до детализации разделов 07–09:

- **OQ-GLOBAL-1 — судьба трёх заглушек. ✅ РЕШЕНО (2026-07-19): заморозить все три.**
  Фокус на План/Сессия/Дневник/Добавки/Настройки. Напоминания / Результаты / Таймер прячем
  из навигации, полноценный BRD по ним пока не пишем (см. краткие «замороженные» файлы 07–09).
- **OQ-GLOBAL-2 — ИА (таббар). ✅ РЕШЕНО как следствие:** таб «Результаты» убираем (тупик,
  его роль играет Дневник) → **4 таба: План · Дневник · Добавки · Настройки**. Таймер остаётся
  частью Сессии. Детали → [раздел 10](10-navigation.md).
- **OQ-GLOBAL-3 — единый слой персиста.** Часть состояния (статус «принято» в Добавках)
  живёт в `localStorage`, а не в SQLite → теряется/не синкается. Договориться: всё
  пользовательское состояние идёт в БД. → разделы 04, и трек «баги».
