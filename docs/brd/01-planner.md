# BRD 01 — План (Planner)

> **Статус реализации:** COMPLETE (функционально работает, код грязноват) · **Приоритет:** P0
> **Роут:** `/planner` (стартовый, `/` → `/planner`) · **Основные сторы:** `planner`, `exercises`, `workouts`, `sessions`
> **Компоненты:** `PlannerTabNext`, `PlannerTabAll`, `NewPlanPopup`, `ExercisePickerPopup`, `CreateExercisePopup`, `EditExercisePopup`, `DayExerciseParamsPopup`, `WorkoutEditPopup`

## 1. Назначение

Главный экран. Здесь пользователь **создаёт тренировочную программу** (цикл дней), **наполняет
тренировочные дни упражнениями** с параметрами (подходы/повторы/интенсивность) и **стартует
тренировку**. Это точка входа в ежедневный сценарий и «витрина» состояния прогресса.

## 2. Пользовательские сценарии

- Как новичок без плана, я хочу с пустого экрана за пару минут собрать программу, чтобы начать тренироваться.
- Как пользователь с планом, я хочу видеть **ближайшую тренировку** первым делом, чтобы сразу её начать.
- Как пользователь, я хочу видеть **весь план** (все дни цикла) и редактировать любой день.
- Как пользователь, я хочу **добавлять/удалять/переставлять** упражнения в дне и настраивать их параметры.
- Как пользователь, пропустивший день, я хочу **сдвинуть** тренировку/сетку, а не «проваливать» её.

## 4. Данные

Читает и пишет (SQLite, `@tauri-apps/plugin-sql`):

- `programs` — программа/цикл (название, дата старта, конфиг: тип цикла, dayOffset, цель, единицы).
- `program_day_exercises` — упражнения дня (day_index, порядок, подходы, повторы, интенсивность, флаг «необязательное»).
- `program_day_workouts` — мета тренировки дня (название, метка микроцикла).
- `exercises` — библиотека упражнений (через стор `exercises`).
- Читает `training_sessions` (для отметки «день выполнен»).

## 5. Состояния экрана

- **Пусто:** нет плана → экран-заглушка + «Создать план».
- **Загрузка:** скелетоны при чтении плана.
- **Наполнено:** вкладки «Ближайшая» / «Весь план».
- **Ошибка:** при недоступной БД — сейчас **молча ничего** (см. §9); нужен явный баннер.
- **Оффлайн:** приложение офлайн-first, отдельного оффлайн-состояния не требуется.

## 6. Валидации и правила

- Недельная сетка: не больше 2 трен-сессий в день (циклическое переключение отдых→1→2→отдых).
- Кастомный цикл: число трен-слотов ≥ заявленного «кол-ва тренировок».
- Сохранение плана — валидация заполненности (название, хотя бы один трен-день).
- «Сдвиг» сохраняет дни отдыха на месте, двигаются только активные дни (sparse rotation).

## 7. Связи с другими разделами

- **Сессия (02):** «Начать тренировку» стартует сессию активного дня.
- **Дневник (03):** выполненные сессии формируют историю и статистику.
- **Напоминания (07):** при сохранении плана с «временем по умолчанию» — предложить автосоздание правил.
- **Добавки (04):** делит модель «ближайший/весь план» и дату старта программы.
- **Настройки (05):** единицы нагрузки (кг/фунты), дефолтный отдых, автотаймер.

## 9. Известные баги и долги (из ревизии кода)

- **Сдвиг цикла ломает старт сессии** (P0-ish): `createSession` пишет `training_sessions.day_index = calendarDay`,
  а `loadSessionExercises` читает `program_day_exercises WHERE day_index = currentSession.day_index`
  (`sessions.api.ts:763, 379, 1210`). При `dayOffset != 0` грузятся упражнения не того дня → нельзя логировать. Есть воспроизводящие тесты `src/__tests__/cycle-shifting.*bug*.test.ts`.
- **Удаление плана стирает историю:** `training_sessions` c `ON DELETE CASCADE` на `program_id`
  (`schema.ts:638`) + `deleteProgram` делает голый `DELETE FROM programs` (`planner.api.ts:125`).
- **«Новый план прячет старый»:** `currentProgram = programs[0]` (order by `created_at DESC`) — второй план молча скрывает первый (`planner.api.ts:31,39`).
- **Долги кода:** `// @ts-nocheck` (Planner.vue:1), обильные `console.log('🔍 Planner…')` (583-651),
  мёртвый закомментированный блок (128-137), неиспользуемый импорт `AppTabs`, `TODO(microcycles)` (572).
- **Дизайн-долг:** геро/таб/пустой-блок SCSS скопирован почти дословно из `Supplements.vue` и `TrainingDiary.vue` — просится общий layout-компонент до рестайла.
