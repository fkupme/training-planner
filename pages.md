# Страницы (детализированно) и концепция первых потоков

Ниже зафиксирован первичный UX/контент. Мои встречные предложения и спорные моменты помечаю тремя звёздочками (\*\*\*).

## 0) Навигация (общая)

- Нижний таббар (`<van-tabbar>`): `План`, `Напоминания`, `Результаты`, `Добавки`, `Таймер`.
- Большинство действий — через нижний попап (`<van-popup>`), как «боттом враппер».
- \*\*\* Предлагаю унифицировать: любой «создать/редактировать» открывает `<van-popup position="bottom">` с формой и кнопками `Сохранить`/`Отмена` закреплёнными в `action-bar`.

## 1) Авторизация / Онбординг

Входной экран — локальная авторизация (пин/биометрия позже), плюс опционально OAuth (через Tauri плагин браузера позже).

Сразу после первого запуска — сбор базовых данных пользователя:

- Поля (обязательные или скипаемые один раз, потом только в Настройках):
  - Возраст, Рост (см), Вес (кг)
  - Стаж тренировок (лет/мес)
  - Фармакология (да/нет) и базовое описание (свободный текст)
  - Силовые (опционально): 1ПМ по базовым (присед, жим, тяга) — пригодится для авто‑подсказок
- Компоненты Vant: `Form`, `Field`, `Picker`, `Radio`, `Switch`, `Button`.
- Валидация: мягкая — можно «Пропустить», но напомним в Плане, что профиль не заполнен, и предложим «заполнить позже».

## 2) Главная: План (если нет плана — пустое состояние)

    - картчочки с напомиананями на сегодня краткие небольше

- статистика по выполнению тренировок с подсветкой весьма краткая просто график с точками на которые можно нажать и посмотреть в тул типе что за тренировка по группам мышц(типо грудь, средняя дельта, трицепс)

- Если план существует:
  - Табы ближайшая тренировка(активный)/план со всеми тренировками
- Если плана нет:
  - Пустой экран с понятным пояснением и кнопкой «Создать план».
- Кнопка «Создать план» → открывает попап «Новый план».

## 3) Попап «Новый план» (настройка цикла)

Шаг 1. Общие

- Название плана
- Дата старта (по умолчанию — сегодня)
- Единицы нагрузки (кг/фунты) — перезапишет глобальные для данного плана

Шаг 2. Тип цикла

- Чекбокс «Недельный цикл» + тултип (объяснение: дни недели фиксированы, повторяются каждые 7 дней).
- Если «Недельный цикл» включён:
  - «Количество тренировок в неделю» (0–14) — Stepper
  - Цель программы: сушка поддержание набор массы набор силы выносливость отдых
  - длительность программы(например есть цель набор будем давать еще процент корректировки веса на упражнениях и раз в пару недель добавлять автоматичкски процентик к весу)
  - Сетка 7 дней (Пн…Вс):
    - Клик по дню — день становится «тренировочным» (градиентом).
    - Повторный клик — день помечается более ярким градиентом = «2 тренировки в день».
    - Третье нажатие — возвращает «день отдыха» (для полного цикла.)
  - Нотификация об изменениях — через `Notify` (нужен `notificationsStore`).
  - Предложение: поле «Время напоминаний по умолчанию» (например, 18:30) для всех трен‑дней.
- Если «Недельный цикл» выключен (кастомный цикл):

  - «Количество дней в цикле» (Stepper)
  - «Количество тренировок в цикле» (Stepper)
  - Расстановка трен‑дней и дней отдыха на ленточной сетке длиной N (дни 1..N) — поведение как у недельной сетки (0/1/2 тренировки/день)
  - Микроциклы (переключатель): - Переключатель «Микроциклы (чередование например лёгкий/тяжёлый/…?)» - Конфиг: количество циклов в пачке (напр. 2) и атрибуты для каждого («лёгкий», «тяжёлый») — метка используется в план‑днях. - Микроциклы имеет смысл разрешить и в недельном режиме (как ты отметил) — включаем одинаковый блок. да однозначно - Чекбокс сохранить как пресест не кликнута если кликнута поле с названием пресета
    Шаг 3. Сохранение

- Кнопка «Сохранить» — закрывает попап → на экране «План» появляется разметка циклов/дней.
- Автогенерация «первой тренировки» (пустой список упражнений) для каждого трен‑дня, чтобы сразу было, куда добавлять.
  и снизу кнопка сохранить с валидацией заполненности

## 4) Экран плана после создания

- По каждому трен‑дню (дата/день цикла/метка микроцикла) — список упражнений.
- Элемент списка «+ Добавить упражнение» — всегда последний.
- Верхний action: «Редактировать план» (открывает тот же попап в режиме редактирования настроек цикла).

## 5) Добавление упражнения

Поиск по библиотеке (через условный `Coupon`‑подобный компонент):

```js
<van-coupon-cell
  :coupons="coupons"
  :chosen-coupon="chosenCoupon"
  @click="showList = true"
/>
<!-- Coupon List -->
<van-popup
  v-model:show="showList"
  round
  position="bottom"
  style="height: 90%; padding-top: 4px;"
>
  <van-coupon-list
    :coupons="coupons"
    :chosen-coupon="chosenCoupon"
    :disabled-coupons="disabledCoupons"
    @change="onChange"
    @exchange="onExchange"
  />
</van-popup>

```

- Слот карточки результата: название, короткое описание, И гифка тоже туда, чипсы мышц (`<van-tag>`), чипсы «оборудование» (гантели/штанга/тяга/тренажёр).
- Последним пунктом — «+ Создать новое упражнение».

Если выбираем существующее:

- Карточка упражнения разворачивается в форму параметров:
  - Подходы: Stepper «кол‑во подходов».
  - Повторы: либо общий Stepper «повторы на все подходы», либо чекбокс «кастомизация по подходам» → таблица повторов `repeat[i]`.
  - Поле «целевая интенсивность» (RPE/RIR) — пригодится для логов и подсказок.
  - Чекбокс «необязательное упражнение» (не влияет на «выполнено» дня).
  - Кнопка «Сохранить».

Если создаём новое упражнение:

- Поля: название, описание, основная мышечная группа, вторичные (multi‑select), оборудование.
- GIF/видео: предлагаю поддержать опциональный локальный файл (позже — CDN/сжатие); сейчас — поле URL/локальный путь (сохранить только ссылку не вариант у нас нет бека брать сторонние ссылки говно затея возьмем раст либу для сжатия гифок и локального хранения).
- После сохранения оно попадает в библиотеку и сразу добавляется в день/план.

## 6) Напоминания (пересечение с Планом)

- При сохранении плана: если задано «время по умолчанию», предложить автосоздание правил напоминаний для трен‑дней.
- Отдельный редактор в «Напоминаниях»: можно перенастроить время/интервалы.
- Дробные интервалы (например, 2.5 дня) — всегда храним как «часы» (60 ч).
- Snooze/Done из уведомления → лог в «Результаты» и пересчёт next_due.

## 7) Логи/результаты (пересечение с Упражнениями)

- При нажатии «Начать тренировку» (с Плана) — открывается сессия: таймер отдыха, ввод подходов (вес/повторы/RPE/заметки).
- Авто‑таймер отдыха: при сохранении подхода запускается отсчёт следующего отдыха; всплывающее напоминание. чекбокс
- По завершении — сохраняем в `results`; карточка дня помечается выполненной.

## 8) Сторы/данные (минимум под MVP)

- `useUserStore`: профиль и флаги онбординга.
- `usePlannerStore`: планы/циклы/дни/связи с упражнениями.
- `useExerciseStore`: библиотека упражнений, кэш поиска.
- `useNotificationsStore`: каналы/правила/состояния Snooze.
- `useSessionStore`: активная трен‑сессия, таймеры.

## 9) Валидации и UX‑штрихи

- Неделя: защищаем от состояния «больше 2 трен‑сессий в день» (цикличное нажатие: отдых → 1 тренировка → 2 тренировки → отдых).
- Кастомный цикл: проверка, что кол‑во трен‑слотов ≥ «кол‑во тренировок».
- Быстрые шаблоны: PPL, UL, FBW — предзадать сетки, чтобы стартануть за 10 секунд.
- Дублировать день/упражнение — ускоряет сборку плана.
- Подсказка объёма: при добавлении упражнения предлагаем «обычный объём» на основе профиля (вес/стаж/1ПМ). Тут нужно еще исходить из цели программы

## Что ещё додумать

- **_ Состояния пропуска дня: не заставляем жать «Начать тренировку». Добавляем интерфейс «Сдвинуть». Если следующий день уже тренировочный — предлагаем сдвинуть ВСЮ сетку вперёд. Если следующий день пуст — даём выбор: сдвинуть всю сетку или только текущую тренировку на +1 день. После сдвига пересчитываем напоминания/next_due и фиксируем лог операции._**
- **_ Пресеты программ/настроек: храним пресеты циклов, микроциклов и шаблонов дней/упражнений. UI: список пресетов с действиями «Применить/Обновить/Удалить». Экспорт/импорт пресетов — JSON._**
- **_ Версии планов (ревизии): откладываем. Для MVP — локальная история правок в процессе редактирования (undo/redo в пределах сессии), полноценные ревизии — позже._**
- **_ Экспорт/импорт JSON: оставляем в «Настройках». Экспорт: все данные/только планы/только пресеты. Импорт: валидация схемы, предпросмотр изменений. Реализация через файловый диалог Tauri._**

Примечания:

- **_ В качестве унифицированного UX для создания/редактирования используем `Popup position="bottom"` + `ActionBar` с CTA — это упростит потоки и сократит разнобой по экранам._**
- **_ Для медиа (GIF/видео) UI делаем на `Uploader`, но хранение/сжатие — натив/таури‑плагин (Rust), чтобы не плодить ссылки и не забивать память без контроля._**
- **_ Для RPE/RIR в формах практичнее `Stepper`/`Slider`, `Rate` оставить опционально (игровой UX)._**
